# 4.0 在线阅读 · 技术方案

> 目标（路线图原文）：实现网页阅读功能，用户可以自己上传 txt 文件进行阅读，同时为部分书目开启阅读功能。
>
> 本文档是基于**当前仓库真实状态**写的方案，不是通用教程。
> 两个现状约束：
> 1. 项目至今**没有任何文件上传功能**（`MultipartFile` 零命中），4.0 是第一个
> 2. `application.yml` **没有 multipart 配置** → Spring 默认单文件上限 **1MB**

---

## 一、先定三个核心决策

### 决策 1：正文存哪？→ **MySQL LONGTEXT**

| 方案 | 优点 | 缺点 | 判断 |
|---|---|---|---|
| **A. MySQL LONGTEXT（推荐）** | 单机零额外设施；`mysqldump` 一次备份全有；正文和书的元数据同事务；正好练大字段 | 不能走 nginx 静态加速；超大文件吃内存 | ✅ 几十本 × 2MB 完全够 |
| B. 磁盘文件 + DB 存路径 | DB 轻；可 nginx 直出 | **部署要管两处**（Windows 开发路径 / Linux 生产路径、目录权限）；备份两处；删记录忘删文件；路径穿越风险 | ❌ 课程项目里是自找麻烦 |
| C. OSS / MinIO | 专业 | 要额外服务 | ❌ 直接排除 |

**关键设计：正文单独建表**（`book_content`），不放在 `book` 里。

理由：`SELECT * FROM book` 是列表页每次都要跑的高频查询，LONGTEXT 即使不参与 `WHERE`，也会被读进结果集。**分表 = 从物理上杜绝**列表页拖 2MB × 20 行。

> 折中策略：**限制而不是优化** —— 单文件上限设 10MB，超过就拒绝。这比上对象存储务实得多。

### 决策 2：正文怎么传？→ **按章节拉取**

| 方案 | 问题 |
|---|---|
| A. 全量一次返回整本 | 100 万字 ≈ 2MB JSON + 100 万字符 DOM → 卡死 |
| **B. 按章节拉（推荐）** | 首屏快、可定位进度、DOM 可控、可预取下一章 |
| C. 固定字数分页（每 5000 字） | 会切在半句话中间，章节标题也会落在页尾 |

代价是必须先做**章节切分**（下文有正则）。

### 决策 3：阅读权限？→ **布尔字段，公开可读**（已拍板）

```sql
ALTER TABLE book ADD COLUMN readable TINYINT(1) NOT NULL DEFAULT 0
  COMMENT '1=开启在线阅读；只有管理员能改';
```

判定规则：

- `readable = 1` **且** `book_content` 里有正文 → **任何登录用户都能读**
- 否则不能读（前端「在线阅读」按钮直接不渲染）

不做"借阅后可读"：少一层状态判断，演示时不用先去借书，点开就能看。

## 二、表设计

```sql
-- ========== 1. 书籍正文（与 book 一对一） ==========
CREATE TABLE book_content (
  book_id       INT       NOT NULL COMMENT '主键即 book.id，一对一',
  content       LONGTEXT  NOT NULL COMMENT '正文纯文本',
  chapters      MEDIUMTEXT COMMENT 'JSON: [{"title":"第一章 xx","start":0,"end":3521}]',
  chapter_count INT       NOT NULL DEFAULT 0,
  word_count    INT       NOT NULL DEFAULT 0 COMMENT '去掉换行后的字符数',
  encoding      VARCHAR(16) COMMENT '检测出的编码：UTF-8 / GB18030 / UTF-16LE',
  create_time   DATETIME  DEFAULT CURRENT_TIMESTAMP,
  update_time   DATETIME  DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (book_id)
) COMMENT '书籍正文';

-- ========== 2. 用户上传的 txt（私有） ==========
CREATE TABLE reader_file (
  id            BIGINT    NOT NULL AUTO_INCREMENT,
  user_id       INT       NOT NULL,
  title         VARCHAR(200) NOT NULL COMMENT '默认取文件名（去扩展名），可改',
  content       LONGTEXT  NOT NULL,
  chapters      MEDIUMTEXT,
  chapter_count INT       NOT NULL DEFAULT 0,
  word_count    INT       NOT NULL DEFAULT 0,
  encoding      VARCHAR(16),
  create_time   DATETIME  DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY idx_user (user_id, create_time)
) COMMENT '用户上传的 txt，只有本人可见';

-- ========== 3. 阅读进度 ==========
CREATE TABLE reader_progress (
  id            BIGINT NOT NULL AUTO_INCREMENT,
  user_id       INT NOT NULL,
  target_type   TINYINT NOT NULL COMMENT '1=书籍 2=上传文件',
  target_id     BIGINT NOT NULL,
  chapter_index INT NOT NULL DEFAULT 0,
  chapter_title VARCHAR(200),
  percent       DECIMAL(5,2) NOT NULL DEFAULT 0 COMMENT '章节内滚动百分比，0~100',
  update_time   DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk (user_id, target_type, target_id)
) COMMENT '一个用户对一个目标只有一条，写入用 ON DUPLICATE KEY UPDATE';
```

> `chapters` 存 JSON 而不是建 `chapter` 表：章节只跟着正文整体替换，**不存在单独改某一章**的场景，建表是过度设计。500 章的 JSON 也就 40KB 左右。

## 三、两个必须写对的工具类

### 3.1 编码检测（国内 txt 最大的坑）

国内 txt 里 **GBK/GB18030 比 UTF-8 还常见**。检测顺序：

```java
public static String decode(byte[] bytes) {
    // 1) BOM 优先
    if (bytes.length >= 3 && (bytes[0] & 0xFF) == 0xEF
            && (bytes[1] & 0xFF) == 0xBB && (bytes[2] & 0xFF) == 0xBF) {
        return new String(bytes, 3, bytes.length - 3, StandardCharsets.UTF_8);
    }
    if (bytes.length >= 2 && (bytes[0] & 0xFF) == 0xFF && (bytes[1] & 0xFF) == 0xFE) {
        return new String(bytes, 2, bytes.length - 2, StandardCharsets.UTF_16LE);
    }

    // 2) 严格 UTF-8 解码：遇到非法字节就抛异常
    CharsetDecoder utf8 = StandardCharsets.UTF_8.newDecoder()
            .onMalformedInput(CodingErrorAction.REPORT)
            .onUnmappableCharacter(CodingErrorAction.REPORT);
    try {
        return utf8.decode(ByteBuffer.wrap(bytes)).toString();
    } catch (CharacterCodingException ignored) {
        // 不是 UTF-8，往下走
    }

    // 3) 退回 GB18030 —— 它是 GBK / GB2312 的超集，
    //    所以不用再单独判断"到底是 GBK 还是 GB2312"
    CharsetDecoder gb = Charset.forName("GB18030").newDecoder()
            .onMalformedInput(CodingErrorAction.REPORT)
            .onUnmappableCharacter(CodingErrorAction.REPORT);
    try {
        return gb.decode(ByteBuffer.wrap(bytes)).toString();
    } catch (CharacterCodingException e) {
        throw new BusinessException("无法识别的文件编码，请另存为 UTF-8 后重新上传");
    }
}
```

**⚠️ 最关键的连带结论：上传必须用 `multipart/form-data` 传原始字节。**

如果前端用 `FileReader.readAsText(file)` 读成字符串再转 JSON 发给后端，浏览器已经按 UTF-8 解码过了 —— **GBK 文件在浏览器端就变成乱码，后端再怎么检测也救不回来**。这不是"最好这样"，是**只能这样**。

### 3.2 章节切分

```java
// (?m) 多行模式 + ^ 锚行首 —— 这一条不能省
private static final Pattern CHAPTER = Pattern.compile(
    "(?m)^[ \\t　]*("
  + "第[0-9０-９零一二三四五六七八九十百千万〇两]+[章节回卷篇集]"
  + "|Chapter\\s+\\d+"
  + "|序章|楔子|引子|尾声|后记|番外"
  + ")[^\\n]{0,40}$"
);
```

四个要点：

1. **`(?m)^` 必须锚行首** —— 否则正文里"他翻到第三章"会被切成章节
2. **`{0,40}` 限制标题长度** —— 章节名不会超过 40 字，防止把一整段匹配掉
3. **允许全角空格 `　`** —— txt 里章节标题常带缩进
4. **必须兜底**：一个章节都没匹配到 → **退化成单章「全文」**，不能报错

```java
List<Chapter> split(String text) {
    List<int[]> marks = new ArrayList<>();
    Matcher m = CHAPTER.matcher(text);
    while (m.find()) {
        marks.add(new int[]{m.start(), m.end()});
    }
    if (marks.isEmpty()) {
        return List.of(new Chapter("全文", 0, text.length()));
    }
    List<Chapter> list = new ArrayList<>();
    // 第一个章节标题之前若还有内容（书名/作者/简介），归入「前言」
    if (marks.get(0)[0] > 0) {
        String head = text.substring(0, marks.get(0)[0]).trim();
        if (!head.isEmpty()) {
            list.add(new Chapter("前言", 0, marks.get(0)[0]));
        }
    }
    for (int i = 0; i < marks.size(); i++) {
        int start = marks.get(i)[0];
        int end = (i + 1 < marks.size()) ? marks.get(i + 1)[0] : text.length();
        String title = text.substring(marks.get(i)[0], marks.get(i)[1]).trim();
        list.add(new Chapter(title, start, end));
    }
    return list;
}
```

**偏移量全部用 `String.indexOf` / `Matcher.start()` 得到的 UTF-16 偏移**，取正文也用 `substring(start, end)` —— 全程同一套坐标，中文和 emoji 都不会切半。

## 四、接口设计

用一个「阅读器」模块统一书籍正文和用户上传文件（`type` 区分），避免两套重复接口。

```
================ 书籍正文（管理员） ================
POST   /reader/books/{bookId}/content        multipart，field=file；上传或替换
DELETE /reader/books/{bookId}/content        删除正文（连带清进度）
PUT    /books/{id}/readable                  改"是否开启阅读"（并入现有图书更新接口亦可）

================ 我的 txt 文件 ================
POST   /reader/files                          multipart，field=file
GET    /reader/files?pageNum&pageSize        我的文件列表
DELETE /reader/files/{id}                    删除（同时删进度）

================ 阅读（type = book | file） ================
GET    /reader/{type}/{id}/meta              目录 + 是否可读 + 上次读到哪
GET    /reader/{type}/{id}/chapter/{index}   单章正文

================ 阅读进度 ================
PUT    /reader/{type}/{id}/progress          { chapterIndex, percent }
```

### 返回结构

```jsonc
// GET /reader/book/12/meta
{
  "code": 1,
  "data": {
    "title": "深海之门",
    "readable": true,          // 当前用户是否有权读
    "denyReason": null,        // 不可读时给人看的原因："需要先借阅"
    "chapterCount": 128,
    "wordCount": 863210,
    "encoding": "GB18030",
    "lastChapter": 37,         // 上次读到第几章，没读过是 0
    "chapters": [
      { "index": 0, "title": "第一章 潜入", "wordCount": 6821 },
      { "index": 1, "title": "第二章 回声", "wordCount": 7210 }
    ]
  }
}
```

```jsonc
// GET /reader/book/12/chapter/37
{
  "code": 1,
  "data": {
    "index": 37,
    "title": "第三十八章 灯灭",
    "content": "他推开那扇门的时候……",
    "prevIndex": 36,
    "nextIndex": 38
  }
}
```

> `meta` 里**不返回正文**，只返回目录；`chapter` 里只返回一章。这样 DOM 和带宽都可控。

## 五、后端配置（容易漏）

```yaml
spring:
  servlet:
    multipart:
      max-file-size: 10MB        # ⚠️ 默认只有 1MB，不改的话随便一本 txt 都传不上
      max-request-size: 12MB
```

其他注意：

- MySQL `max_allowed_packet` 默认 **64MB** → 10MB 的文件没问题，不用调
- `LONGTEXT` 上限 4GB → 不用管
- 正文入库前把 `\r\n` 统一成 `\n`（Windows txt 全是 `\r\n`，会影响正则和字数统计）
- 项目里配了 Redis，但**阅读进度不要放 Redis** —— 它是必须持久化的小数据，一条 MySQL 记录就够

## 六、前端设计

### 6.1 路由：阅读页必须脱离 MainLayout

```js
// router/index.js —— 平级路由，不放进 '/' 的 children
{
  path: '/read/:type/:id',
  name: 'reader',
  component: () => import('@/views/reader/ReaderView.vue'),
  meta: { title: '阅读' }
}
```

**这是整个 4.0 最重要的一个 UI 决策**：阅读页不套 `MainLayout`（没有侧边栏、没有顶栏）。沉浸感是阅读页的全部价值，留着 220px 侧边栏就没有"在读书"的感觉了。

### 6.2 阅读页布局

```
┌──────────────────────────────────────────────────┐
│  ←   深海之门              目录   A−  A+   ◐     │ ← 工具栏，滚动时淡入
├──────────────────────────────────────────────────┤
│                                                  │
│                第三十八章  灯灭                    │
│                                                  │
│      他推开那扇门的时候，灯正好灭了。走廊尽头      │ ← 正文 max-width: 34em
│      传来水声，像有人在很深的地方呼吸……           │    line-height: 1.9
│                                                  │
│                                                  │
│              ← 上一章          下一章 →           │
└──────────────────────────────────────────────────┘
```

排版参数（这些数字是有依据的）：

| 项 | 值 | 为什么 |
|---|---|---|
| 正文列宽 | `max-width: 34em` | 一行 30~36 个汉字是中文阅读的舒适区 |
| 行高 | `1.9` | 中文没有词间距，行距要比英文松 |
| 字号 | 16~24px，默认 18px | ± 按钮调整，存 localStorage |
| 字距 | `.01em` | 微松 |
| 段落缩进 | `text-indent: 2em` | 中文排版惯例 |
| 主题 | **白 / 黑** 两档 | 不做"纸黄" —— 会破坏黑白系统 |

### 6.3 关键实现点

```vue
<!-- 正文渲染：必须用插值 + pre-wrap，绝对不能用 v-html -->
<p class="para">{{ chapter.content }}</p>
```
```css
.para { white-space: pre-wrap; }
```

**为什么不能用 `v-html`**：txt 里可能带 `<script>` 或 `<img onerror=...>`，用户上传的文件是不可信输入 → 直接 XSS。`{{ }}` 插值会自动转义 ✓

其他：

- **键盘翻章**：`←` / `→`，`Esc` 关目录
- **进度保存**：切章时 `PUT progress`（节流 1s），进入时跳到 `lastChapter`
- **预取**：当前章渲染完后，悄悄请求 `chapter/{nextIndex}` 缓存起来 —— 翻下一页是瞬时的
- **工具栏自动隐藏**：滚动向下隐藏、向上显示（阅读时不想被工具栏挡着）
- **目录抽屉**：`el-drawer`，500 章要虚拟滚动或用 `scroll-into-view` 定位到当前章

### 6.4 上传页

- `el-upload` 的 `:http-request` 自定义（要自己带 `Authorization` 头）
- 前端只校验 **扩展名 `.txt`** 和 **大小 ≤10MB**
- **不读文件内容** —— 编码交给后端
- 上传成功 → 后端直接返回 `id + chapterCount` → 立即 `router.push('/read/file/' + id)` ✓

### 6.5 "部分书目开启阅读"的入口

| 位置 | 变化 |
|---|---|
| 图书编辑弹窗 | 加「在线阅读」下拉（未开启 / 公开可读 / 借阅后可读）+ 「上传正文」按钮 |
| 图书详情抽屉 | `readMode > 0` 且有正文 → 显示「在线阅读」按钮 |
| 图书列表 | 书名旁加一个小的「可读」标记（不用彩色，用描边小标签） |

## 七、八个坑（按踩到概率排序）

| # | 坑 | 后果 | 处理 |
|---|---|---|---|
| 1 | Spring 默认 `max-file-size=1MB` | 1MB 以上的 txt 直接被拒（413） | 改 `application.yml` |
| 2 | 前端 `readAsText` 再传 | GBK 文件在**浏览器端**就乱码，后端救不回 | 必须 multipart 传原始字节 |
| 3 | 章节正则不锚 `(?m)^` | 正文里"他翻到第三章"被当成章节 | 锚行首 + 标题长度上限 |
| 4 | 书列表 `SELECT *` 带出正文 | 列表页每次拖 2MB × 20 行 | 正文单独建表 |
| 5 | `v-html` 渲染正文 | XSS（用户上传的文件不可信） | 插值 + `pre-wrap` |
| 6 | 一次渲染整本 | 100 万字 DOM 直接卡死 | 按章拉取 |
| 7 | 章节偏移用字节算 | 中文 / emoji 被切半成乱码 | 全程 UTF-16 偏移（`indexOf`/`substring`） |
| 8 | 拿用户文件名当存储名 | 路径穿越 / 同名覆盖 | 不落磁盘，只存 DB |

## 八、分阶段实施

| 阶段 | 内容 | 估时 |
|---|---|---|
| **P1 后端地基** | 建表 + multipart 配置 + 编码检测工具 + 章节切分工具 + `meta` / `chapter` 接口 | 2~3h |
| **P2 阅读器** | `ReaderView`：工具栏 / 正文排版 / 目录 / 字号 / 主题 / 键盘 / 进度 | 3~4h |
| **P3 用户上传** | 上传接口 + 我的文件列表 + 上传后直接进入阅读 | 2h |
| **P4 书开启阅读** | `read_mode` 开关 + 管理员上传正文 + 详情页入口 + 列表标记 | 1~2h |
| **P5 边界** | 未开启 / 无正文 / 无权限 / 超大文件 / 空章节 / 超长章节 | 1h |

**总计约 9~12 小时。**

## 九、明确不做（YAGNI）

| 不做 | 理由 |
|---|---|
| ❌ PDF / EPUB 支持 | 要 pdf.js / epub.js，等于再做一个项目 |
| ❌ 真正的"翻页"动效 | 分页计算极其复杂（要按容器高度切文本），滚动 + 章节已经够 |
| ❌ 全文搜索 | 只有几十本书，MySQL 的 `LIKE` 都嫌慢，用不上 |
| ❌ 书签 / 笔记 / 划词高亮 | 属于"阅读社区"，不是"阅读器" |
| ❌ 字体切换（衬线/无衬线） | 先用系统默认，做了也没人切 |
| ❌ 语音朗读 | 与本项目主线无关 |
| ❌ 用 Redis 缓存正文 | 正文是冷数据，缓存命中率低还占内存 |

## 十、已拍板

**只做「公开可读」** → 用 `book.readable` 布尔字段。

- ✅ 开启即读，不用先借书，演示时点开就能看
- ❌ 不做「借阅后可读」
- ❌ 不做「两档都支持」

以后若要加「借阅后可读」，只需把 `readable` 换成三值字段，并在**可读性校验那一处**
多一个"存在 `status=1` 的借阅记录"的判断 —— 改动集中在一个方法里，不会扩散。
