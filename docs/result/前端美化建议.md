# 前端美化建议

> 前提：这套界面已经有**明确的设计系统**（`library-web/src/styles/theme.css`，风格 B「黑白强对比」）。
> 所以本文的立场是 —— **在这个系统里做加法，不要推翻它**。
> 下面每一条都标了「感知提升 / 工作量」，最后有一节专门写**不建议做的**。

---

## 〇、先说已经做对的（别动）

| 已经在做的 | 为什么别动 |
|---|---|
| 纯黑白灰 + 只有一个 `--alert` 红 | 这是整套界面的**识别度**来源。加第二个颜色就毁了 |
| 除弹窗外零阴影，层级全靠 1px 发丝线 | 一旦给卡片加阴影，立刻变成"上个世纪的 Bootstrap 后台" |
| 4/5/8px 小圆角 | 大圆角（12px+）是移动端语汇，放管理后台会显得不专业 |
| 只有 120ms 颜色过渡，不做位移/缩放 | 克制。乱加动画比不加更廉价 |
| `.tnum` 等宽数字 | 表格里数字上下对齐，这个细节 90% 的课程项目没有 |
| 表头上下两条黑线（年报式） | 很有质感的一处，别改成灰底 |

**结论：这套皮是好的，缺的是"信息密度"和"打磨细节"，不是"换个颜色"。**

---

## 一、优先级最高（性价比排序）

### 1. 加图标 ★★★ 零成本

**为什么第一**：图标库 `@element-plus/icons-vue` **已经装好并在 `main.js` 全局注册了**，
现在却一个都没用 —— 侧边栏是纯文字的，这是整站最"素"的地方。

```html
<!-- MainLayout 侧边栏：文字前加图标 -->
<router-link to="/books" class="nav-item" active-class="is-active">
  <el-icon><Reading /></el-icon>
  <span>图书管理</span>
</router-link>
```

配套改一下 `.nav-item` 的间距和对齐（`gap: 8px` 已有）。建议给 6 个菜单配：

| 菜单 | 图标 |
|---|---|
| 图书管理/查询 | `Reading` |
| 通知公告 | `Bell` |
| 我的借阅 / 借阅管理 | `Tickets` |
| 用户管理 | `User` |
| 个人中心 | `Setting`（或 `Avatar`） |
| 在线阅读（4.0 占位） | `Notebook` |

再用在：空状态 `<el-empty><el-icon><Box /></el-icon>`、按钮图标（`<el-button :icon="Plus">新增图书`）、
搜索框 `prefix-icon="Search"`。

> ⚠️ 图标**只用来辅助识别，不要用来装饰**。一个菜单一个，别加第二个。

### 2. 做一个首页/工作台 ★★★ 感知提升最大

**现状**：`/` 直接 redirect 到 `/books`。整个系统**没有首页** —— 打开就是一张大表格，
这是"像个完整系统"和"像个 CRUD demo"最大的分水岭。

**读者视角的首页**（数据全都现成）：

```
┌─ 我的借阅 ──────────────┐  ┌─ 通知 ───────────────────┐
│  在借 2 本              │  │ 📌 国庆闭馆安排            │
│  🔴 逾期 1 本           │  │    新书上架通知            │
│  累计 9 本              │  │    未读 3 条 →             │
└────────────────────────┘  └──────────────────────────┘
[去查书]  [我的借阅]
```

**管理员视角多三块**：今日借出/归还、**逾期名单**（前 5 条，直接催）、**库存告警**（可借为 0 的书）。

**用的接口**（一个都不用新写）：
`/borrows/my/summary`、`/notices/unread-count`、`/notices?onlyTop=1&pageSize=3`、
`/borrows?overdue=1&pageSize=5`（管理员）、`/users?...`（管理员）。

> ⚠️ **别堆数字**。4 个就有用，12 个就是噪音。
> 判断标准：**这个数字出现后，用户会去做一件具体的事吗？** 会 → 留；不会 → 删。

### 3. 表头吸顶 + 分页吸底 ★★

**现状**：整页滚动，滚到第 30 行时**表头已经看不见了**，不知道自己看的是哪一列。
这是后台表格最典型的"不够专业"。

Element Plus 原生支持，给 `el-table` 一个高度就行：

```html
<el-table :height="tableHeight" ...>
```
```js
// 容器高度 - 工具条 - 分页
const tableHeight = 'calc(100vh - 260px)'
```

设了 `height` 之后：**表体自己滚动、表头固定**，分页也跟着留在底部不动。

> 顺带：`el-table` 还支持 `border`、`stripe`，但**这两个都不要开** ——
> `border` 会把发丝线变成网格（廉价），`stripe` 的斑马纹会被你的行 hover 和逾期红底打架。

### 4. 空状态要分两种 ★★ 极低成本

**现状**：所有表格的空状态都是 `<el-empty description="暂无图书数据" />`。
问题：**"库里真的没书"和"筛选后没结果"长得一模一样** —— 后者用户会以为系统坏了。

```html
<template #empty>
  <!-- 有筛选条件 → 提示放宽条件，并给一个重置按钮 -->
  <el-empty v-if="hasFilter" description="没有符合条件的图书">
    <el-button @click="handleReset">清空筛选条件</el-button>
  </el-empty>
  <!-- 真的没数据 → 提示下一步动作（管理员才有） -->
  <el-empty v-else :description="isAdmin ? '还没有图书，点右上角「新增图书」开始' : '图书馆还没有录入图书'" />
</template>
```
```js
const hasFilter = computed(() =>
  !!(queryParams.isbn || queryParams.name || queryParams.author ||
     queryParams.categoryId !== null || queryParams.status !== null)
)
```

### 5. 登录页改成左右分栏 ★★ 第一印象

登录页是**老师和答辩评委看到的第一屏**。现在是一个居中小卡片，比较单薄。

```
┌──────────────────────┬─────────────────┐
│                      │                 │
│   [logo] 星河图书      │   用户名  [   ]  │
│   让每一本书都被找到    │   密码    [   ]  │
│                      │   [   登 录   ]  │
│   ·借阅规则一句话       │                 │
│   ·测试账号卡片         │   还没有账号？注册 │
└──────────────────────┴─────────────────┘
```

左边用纯色块 + 一个超大号的品牌字（黑白系统里，**大字排版就是最好的装饰**），
右边保持现在的表单。**不要加插画/渐变**，那会破坏风格。

## 二、低成本高感知的细节清单

| # | 做什么 | 怎么做 | 工作量 |
|---|---|---|---|
| 1 | **页面切换淡入** | `<router-view v-slot="{ Component }"><transition name="fade"><component :is="Component"/></transition></router-view>`，`.fade-enter-active{transition:opacity 120ms}`（**只淡入，不位移**，守住设计原则） | 10 分钟 |
| 2 | **键盘焦点可见** | 全局加 `:focus-visible { outline: 2px solid #000; outline-offset: 2px }` —— 现在用 Tab 键操作时几乎看不出焦点在哪（无障碍问题） | 5 分钟 |
| 3 | **骨架屏替代转圈** | 列表首次加载用 `<el-skeleton :rows="6" animated />`，之后的翻页仍用 `v-loading` | 20 分钟 |
| 4 | **表格数字右对齐** | 定价、册数、天数一律 `align="right"` + `.tnum`，这是财务报表的标准做法 | 10 分钟 |
| 5 | **危险操作二次确认统一** | 现在的确认框文案有的带书名、有的不带。统一成「动作 + 对象 + 后果」三段式 | 20 分钟 |
| 6 | **表单错误聚焦** | 提交失败时 `formRef.value.scrollToField(firstErrorField)`，长表单（图书新增）体验差别很大 | 20 分钟 |
| 7 | **顶栏加面包屑** | 二级页面（详情页）显示 `图书管理 / 红楼梦`，让"我在哪"一目了然 | 30 分钟 |
| 8 | **hover 时显示操作** | 表格操作列平时淡一点（`opacity: .55`），行 hover 时变实 —— 减少视觉噪音 | 15 分钟 |
| 9 | **统计数字加单位小字** | 已有（`.unit` 那套）✅ 继续保持 | — |
| 10 | **favicon / 标签页标题** | 已有 ✅ | — |

## 三、中等成本（想做再做）

### 1. 深色模式 ★★★ 效果最"哇"，但要先做一次审计

**好消息**：这套主题**全部走 CSS 变量**（`theme.css` 的 `:root` 里定义了 40+ 个 token，
外加 ~30 个 `--el-*` 覆盖），所以"换皮"本身是机械工作 ——
只要在 `html.dark` 下重新定义同一批变量即可。而且 **Element Plus 自带深色主题**：

```js
import 'element-plus/theme-chalk/dark/css-vars.css'   // main.js
```
```css
/* theme.css：把 :root 的那批 token 复制一份，值换成深色 */
html.dark {
  --ink-1: #f5f5f5;
  --surface: #0a0a0a;
  --canvas: #000;
  --line: #262626;
  /* … 约 40 个 */
}
```
再配一个切换按钮（`localStorage` 记住选择）。

**但有个坑**：现在有些地方**硬编码了 `#000` / `#fff`**，深色下会瞎。需要逐个换成变量：

| 位置 | 现在 | 应该 |
|---|---|---|
| `.role-chip.is-admin` / `.pin-tag` / `.badge` | `background: #000; color: #fff` | `var(--ink-1)` / `var(--surface)` |
| `.stat-v b`、`.book-name`、`.notice-title.is-unread` | `color: #000` | `var(--ink-1)` |
| `.el-table th` 的上下黑线 | `1px solid #000` | `var(--ink-1)` |
| `.status-dot.is-on`、`.chip .dot` | `background: #000` | `var(--ink-1)` |
| `theme.css` 里的 `--el-button--primary` 等 | `#000` / `#262626` | 保持（深色下主按钮要反过来，得单独写） |

**工作量估计**：机械改 20~30 处 + 手工验证每个页面。**这是最容易被低估的一条** ——
要不要做，取决于你答辩时想不想多一个亮点。

### 2. 侧边栏可折叠 ★★ 顺手解决一个真问题

**先说一个实测出来的问题**：图书列表在 **1366×768 的笔记本/教室投影**上会**横向滚动**。

```
管理员的图书表：选择44 + 封面60 + 书名220 + 作者140 + 出版社160 + 分类88
              + 定价92 + 可借100 + 状态112 + 操作168 = 1184px
页面左右 padding 24×2                                  =   48px
合计                                                   ≈ 1232px

1366 屏可用宽度 = 1366 - 侧边栏 220 = 1146px  → 差 86px，必须横向滚
```

**折叠侧边栏直接把 220px 变成 56px**，释放 164px → 1366 屏就够了 ✅

而且折叠后是"图标栏"，正好**依赖第 1 条的图标**（做完图标才能折叠）。

### 3. 响应式收尾

- `<1366px`：隐藏「出版社」「分类」两列（`v-if` + `window.innerWidth`，或 CSS media query）
- `<900px`：侧边栏默认折叠
- 目标不是手机端（管理后台不需要），而是**教室投影和 13 寸笔记本**。

## 四、高成本 / 看情况

| 项 | 说明 | 值不值 |
|---|---|---|
| **借阅统计图表**（ECharts） | 管理端加"近 30 天借阅趋势""分类占比""借阅排行榜" | 答辩加分明显，但要加一个依赖 + 后端补聚合接口。**时间够就做** |

| **虚拟滚动** | 数据量大时用 `el-table-v2` | ⛔ 课程项目数据量用不上，别做 |

## 五、★ 我不建议做的（保护现在的克制感）

| 别做 | 为什么 |
|---|---|
| ❌ 换一套彩色主题 / 加主色调渐变 | 会直接毁掉 B 版最强的那一点：**克制** |
| ❌ 给卡片、表格加阴影 | 设计系统明确"除弹窗外零阴影"。加了立刻变成廉价模板 |
| ❌ 加大面积圆角（12px+）、彩色标签 | 现在圆角 4/5/8px 是刻意的小，彩色标签会压过 `--alert` 的警示作用 |
| ❌ 给每个元素加入场动画 | 位移/缩放已被设计系统排除；动效越多越显得心虚 |
| ❌ 引入第二套 UI 库或现成后台模板 | 会和你现在的主题打架，且失去"自己写的"这个学习价值 |
| ❌ 为了"满"堆积仪表盘数字 | 首页 4 个有效数字 > 12 个没人看的数字 |
| ❌ 把表格改成卡片列表 | 管理后台的信息密度靠表格，卡片化会让一屏只能看 6 条数据 |

---

## 六、如果只做三件事

按「感知提升 ÷ 工作量」排序，我会选：

1. **加图标**（零依赖、已全局注册，30 分钟）—— 立竿见影，侧边栏立刻不素了
2. **做首页/工作台**（用现成接口，半天）—— 从"CRUD demo"变成"一个系统"
3. **表头吸顶 + 空状态分两种**（1 小时）—— 表格类界面专业度的两个关键细节

做完这三件，整个站点的观感会跳一个台阶；`深色模式` 和 `图表` 属于"时间充裕再加分"的档位。
