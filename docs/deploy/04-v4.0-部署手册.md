## 二、nginx 配置（现状，勿随意改动）

`/www/server/panel/vhost/nginx/library.conf`：

```nginx
server {
    listen 80;
    server_name 8.129.83.62;
    root /www/wwwroot/library/dist;
    index index.html;
    client_max_body_size 20m;

    location /api/ {
        proxy_pass http://127.0.0.1:8081/;   # 注意结尾的 /，会剥掉 /api 前缀
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    location / {
        try_files $uri $uri/ /index.html;    # history 路由回退
    }
}
```

> ⚠️ 这里**没有** `/uploads/` 的转发。前端有个封面图上传功能会请求 `POST /files/upload`，
> 但后端目前根本没有这个接口 —— 封面功能是断的（见文末"已知缺口"）。

## 三、后端服务定义

`/etc/systemd/system/library-app.service`：

```ini
[Unit]
Description=Library Manager System
After=network.target

[Service]
Type=simple
WorkingDirectory=/www/wwwroot/library
EnvironmentFile=/www/wwwroot/library/app.env
ExecStart=/usr/bin/java -Xms256m -Xmx512m -XX:MaxMetaspaceSize=192m -XX:+UseSerialGC -Duser.timezone=Asia/Shanghai -jar /www/wwwroot/library/app.jar --spring.datasource.username=library_system --spring.datasource.password=${DB_PASSWORD}
Restart=always
RestartSec=5
```

> `${DB_PASSWORD}` 是由 systemd 从 `EnvironmentFile` 展开的，进程命令行里能看到明文，
> 用 `ps` 能瞄到。要避免就改成让 `application.yml` 自己读 `DB_PASSWORD`（它本来就支持），
> 把这两个 `--spring.datasource.*` 参数删掉即可。

`/www/wwwroot/library/app.env`（权限 600，内容脱敏）：

```ini
DB_PASSWORD=***
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
REDIS_PASSWORD=***
JWT_SECRET=***        # openssl rand -base64 48 生成，≥32 字节
```

## 四、日常发布流程（4 步，约 3 分钟）

### 前置：本机打包

```powershell
cd "D:\java\IDEA project\library_manager_system"

# 后端
cd libaray_manager_system
mvn -B -DskipTests clean package
# 产物：target\libaray_manager_system-0.0.1-SNAPSHOT.jar（约 42 MB）

# 前端
cd ..\library-web
npm run build
# 产物：dist\（约 1.7 MB）
```

### 第 1 步：备份（每次都做，30 秒）

```bash
ssh root@8.129.83.62
TS=$(date +%Y%m%d-%H%M%S)
BK=/www/wwwroot/library/backup/$TS
mkdir -p $BK
cp /www/wwwroot/library/app.jar $BK/app.jar.bak
cp -r /www/wwwroot/library/dist $BK/dist.bak
mysqldump -ulibrary_system -p"$DB_PASSWORD" --single-transaction library_system > $BK/library_system.sql
echo "备份到 $BK"
```

### 第 2 步：数据库变更（**只有改了库才做，且必须在新 jar 之前**）

```powershell
scp "docs\sql\04-v4.0-在线阅读建表.sql" root@8.129.83.62:/tmp/migrate.sql
```
```bash
mysql -ulibrary_system -p"$DB_PASSWORD" --default-character-set=utf8mb4 < /tmp/migrate.sql
```

顺序不能反：新 jar 的 `BookMapper.xml` 会 SELECT `readable` 列，
先换 jar 后改库会导致**图书列表全部 500**。

### 第 3 步：换后端

```powershell
scp "libaray_manager_system\target\libaray_manager_system-0.0.1-SNAPSHOT.jar" root@8.129.83.62:/tmp/app-new.jar
ssh root@8.129.83.62 "md5sum /tmp/app-new.jar"
# 与本机 Get-FileHash 对照一致再继续
```
```bash
cp /www/wwwroot/library/app.jar /www/wwwroot/library/app.jar.old
cp /tmp/app-new.jar /www/wwwroot/library/app.jar
chmod 644 /www/wwwroot/library/app.jar
systemctl restart library-app
journalctl -u library-app -f        # 等到 "Started ... in x seconds"
```

### 第 4 步：换前端（目录整体替换，避免旧 hash 文件堆积）

```powershell
scp -r "library-web\dist" root@8.129.83.62:/tmp/dist-new
```
```bash
cd /www/wwwroot/library
mv dist dist.old-$(date +%Y%m%d-%H%M%S)
mv /tmp/dist-new dist
chown -R root:root dist && chmod -R 755 dist
# 静态文件不需要 reload nginx
```

## 七、Redis 安装踩坑记录（重要，换机器复现必看）

Ubuntu 26.04 默认的 `redis-server.service` 有硬化沙箱，直接装完起不来。本次踩了 3 个坑：

### 坑 1：`libjemalloc.so.2: failed to map segment from shared object`

systemd 日志报这个，但**手动跑 `/usr/bin/redis-server` 完全正常**。

根因：本机 `/usr/local/lib/` 下另有一份 `libjemalloc.so.2`（`ldd` 显示实际加载的是它），
而 Ubuntu 默认 unit 里有：

```ini
NoExecPaths=/
ExecPaths=/usr/bin/redis-server /usr/lib /lib
```

`/usr/local/lib` 不在白名单里 → 映射被拒。

解决（drop-in，只放开这一项，其余硬化全部保留）：

```bash
mkdir -p /etc/systemd/system/redis-server.service.d
cat > /etc/systemd/system/redis-server.service.d/override.conf <<'EOF'
[Service]
NoExecPaths=
ExecPaths=
EOF
systemctl daemon-reload
```

### 坑 2：`Can't open the log file: Permission denied`

之前用 root 手动跑过 redis，生成了 `/var/log/redis/redis-server.log`（属主 root），
导致服务以 `redis` 用户启动时写不进去。

```bash
chown -R redis:adm /var/log/redis && chmod 2750 /var/log/redis
rm -f /var/log/redis/redis-server.log
```

### 坑 3：`WARNING Memory overcommit must be enabled`

低配机器（1.7 GB 内存）建议开启：

```bash
echo 'vm.overcommit_memory = 1' > /etc/sysctl.d/99-redis-overcommit.conf
sysctl -w vm.overcommit_memory=1
```

> 注：Ubuntu 26.04 **没有** `/etc/sysctl.conf`，别往那儿写。

### Redis 配置（本次追加在 `/etc/redis/redis.conf` 末尾）

```ini
requirepass <随机 32 位十六进制>
maxmemory 64mb
maxmemory-policy allkeys-lru
```

## 八、PowerShell 传脚本的坑（自己踩的，记下来）

用 `Get-Content xxx.sh -Raw | ssh root@host "bash -s"` 的方式远程执行脚本时，
**PowerShell 会把每一行换成 CRLF** 再喂给 bash，导致：

- `$'\r': command not found`
- 更阴的：变量末尾带 `\r`，于是 `CONF=/etc/redis/redis.conf` 变成了另一个文件名，
  配置被写进野文件，`systemctl` 起不来还查不出原因

**正确姿势**：

```powershell
scp .deploy\xxx.sh root@8.129.83.62:/tmp/x.sh
ssh root@8.129.83.62 "tr -d '\r' < /tmp/x.sh > /tmp/y.sh; bash /tmp/y.sh"
```

## 九、已知缺口（与本次部署无关，但需要知道）

1. **封面图上传功能是断的**：前端 `src/api/file.js` 调 `POST /files/upload`，
   后端没有该接口，nginx 也没有 `/uploads/` 转发。要修得后端补 FileController + 静态资源映射。
2. **JWT 密钥已换成随机值**：所有已登录用户的 token 立即失效，需要重新登录（这是安全修复）。
3. **内存偏紧**：可用约 430 MB，JVM 堆上限 512 MB。若再加服务建议先升配或调小 `-Xmx`。
4. **`8081` / `3306` 监听在 `0.0.0.0`**：目前靠阿里云安全组挡住外网，但更稳妥的做法是
   改成 `server.address=127.0.0.1`（后端）和 MySQL `bind-address=127.0.0.1`。
