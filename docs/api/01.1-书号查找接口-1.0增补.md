## 〇、这次改了什么（一句话）

**没有新开接口。** 只是给原有的列表查询 `GET /books` **多了一个可选的筛选条件 `isbn`**，和书名、作者、分类一样参与分页查询。

| 类别 | 内容 | 影响 |
|---|---|---|
| 🔧 **原有接口增强** | `GET /books` 新增可选参数 `isbn`（精确匹配） | **向后兼容**：不传这个参数，接口行为和以前完全一样 |
| 🔧 **类属性新增** | `BookQueryDTO` 加一个 `isbn` 字段 | 加了不填就没有影响 |
| 🔧 **Mapper 新增** | 列表 XML 的 `<where>` 里加一个 `<if>` | — |
| 🔧 **前端新增** | 筛选区多一个「书号（精确）」输入框 | — |
| ❌ **没有新增接口** | 原来那 9 个接口，一个都没多、一个都没少 | — |

> **设计取舍记录**：我最初做成了独立接口 `GET /books/isbn/{isbn}`（带"查不到就引导录入"的流程），
> 后来改回列表筛选 —— 书号本来就是**筛选条件**的一种，跟书名/作者并排、共用分页逻辑，代码更少、心智负担更低，
> 后端也不用多维护一个方法。那版设计已完全撤除（前端代码、接口文档都清干净了）。

## 一、接口改动详情

### 1.1 请求（在原接口上增加一个参数）

| 项 | 值 |
|---|---|
| 请求方法 | `GET`（没变） |
| 后端路径 | `/books`（没变） |
| 前端请求 | `/api/books?pageNum=1&pageSize=10&isbn=9787020002207` |

**`GET /books` 的完整参数表**（🆕 标的是本次新增的）

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `pageNum` | Integer | 否 | 第几页，默认 1 |
| `pageSize` | Integer | 否 | 每页几条，默认 10 |
| 🆕 `isbn` | String | 否 | **书号，精确匹配**（不是模糊） |
| `name` | String | 否 | 书名，模糊匹配 |
| `author` | String | 否 | 作者，模糊匹配 |
| `categoryId` | Integer | 否 | 分类 id，精确匹配 |
| `status` | Integer | 否 | 状态：1 在架 / 0 下架 |

**请求示例**

```
GET /books?pageNum=1&pageSize=10&isbn=9787020002207
GET /books?pageNum=1&pageSize=10&isbn=9787020002207&status=1     ← 可以和别的条件组合
```

```json
        "coverUrl": null,
        "intro": "中国古典四大名著之一……",

        "createTime": "2026-10-12 20:30:00",
        "updateTime": "2026-10-12 20:30:00"
      }

```

**书号在馆藏里不存在时**（跟"没有符合条件的书"是同一种情况，不需要特殊处理）：

```json
{ "code": 1, "msg": "success", "data": { "total": 0, "list": [] } }
```

> 这就是列表筛选的好处：**"没这本书"天然就是"空列表"**，前端表格直接显示"暂无图书数据"，不需要额外约定。
> （上一版独立接口为了让前端区分"没查到"和"接口报错"，还得特意约定 `code:1 + data:null`，多一层心智负担。）

### 1.3 ⚠️ 为什么用精确匹配，不用模糊匹配

- ISBN 是**唯一标识**（数据库上有唯一索引 `uk_book_isbn`），没有"模糊"的业务含义
- 精确匹配能**走索引**，查询快
- 用户少打一位数字就模糊命中一堆书，反而容易误判

**但有个实用性处理**：用户从豆瓣/淘宝复制的书号常带连字符或空格（`978-7-02-000220-7`、`978 7 02 000220 7`），
所以**前端在发请求前会把 `-` 和空格去掉**（`src/api/book.js` 的 `pageBooks` 里做了统一处理），
后端拿到的永远是纯数字。

> 如果你希望**支持部分书号**查询（比如只输后 6 位），把 XML 里的 `=` 改成 `LIKE CONCAT('%', #{isbn}, '%')` 即可，
> 但要注意那样就用不上唯一索引了。**当前实现是精确匹配。**

## 二、后端要改的地方（3 处）

### 2.1 `BookQueryDTO` 加一个属性

```java
/** 书号，精确匹配 */
private String isbn;
```

### 2.2 `BookMapper` XML 的列表查询加一个 `<if>`

在原来那个 `<where>` 里加（**注意：条件是 `b.isbn = #{isbn}`，不是 LIKE**）：

```xml
<select id="list" resultType="org.libaray_manager_system.pojo.vo.BookVO">
    SELECT b.*, c.name AS category_name
    FROM book b
    LEFT JOIN book_category c ON b.category_id = c.id
    <where>
        <if test="isbn != null and isbn != ''">
            AND b.isbn = #{isbn}
        </if>
        <if test="name != null and name != ''">
            AND b.name LIKE CONCAT('%', #{name}, '%')
        </if>
        <if test="author != null and author != ''">
            AND b.author LIKE CONCAT('%', #{author}, '%')
        </if>
        <if test="categoryId != null">
            AND b.category_id = #{categoryId}
        </if>
        <if test="status != null">
            AND b.status = #{status}
        </if>
    </where>
    ORDER BY b.create_time DESC, b.id DESC
</select>
```

> `<where>` 标签会自动处理第一个 `AND`，也会在**一个条件都没有时什么都不拼** ——
> 所以"五个条件全不传 = 查全部"依然成立，老前端调用方式（只传分页）也完全不受影响。

### 2.3 Controller 和 Service **不用改**

`BookController` 里原来是 `page(BookQueryDTO query)` 接收查询参数，
`BookQueryDTO` 加了 `isbn` 字段之后，Spring 会自动把 `?isbn=xxx` 绑上去 —— **一行代码都不用动**。

| 文件 | 改动 |
|---|---|
| `src/api/book.js` | `pageBooks()` 增加书号规范化（去掉 `-` 和空格）；注释里补上 `isbn` 参数 |

