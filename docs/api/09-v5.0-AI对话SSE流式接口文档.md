# 5.0 AI 对话 · SSE 流式接口文档（P1）

> 这份文档对应 **P1：流式输出**。接口语义、事件协议、后端实现、前端解析、踩坑，一篇写全。
>
> 前端已按**方案 C（开关切换）**接入：`AiChatView.vue` 里的 `USE_STREAM` 默认 `false`，
> 后端接口写完、联调通过后改成 `true` 即可切换；非流式 `/ai/chat` 保留不动。

---

## 〇、P1 做什么

| 做 | 不做（P2/P3） |
|---|---|
| 用户提问后**逐字**显示回答 | 多轮上下文（P2） |
| 保留非流式接口做对照/降级 | 会话列表、历史消息（P2） |
| 客户端断开时停止生成 | 工具调用（P3） |
| 演示模式（mock）也能流式 | 每日额度（P4） |

⚠️ 流式不是“更快的接口”，而是**同一个回答分多次写出去**。总耗时不会变短，但首字出现的时间从 3 秒变成 0.3 秒。

## 一、为什么是 SSE + SseEmitter

### 1.1 SSE vs 其他方案

| 方案 | 适合吗 | 原因 |
|---|---|---|
| **SSE（推荐）** | ✅ | 单向（服务器→浏览器）、纯文本、HTTP 原生、断线浏览器会自动重连（EventSource） |
| WebSocket | ❌ | 双向能力用不上；还要处理握手、心跳、重连、鉴权 |
| 轮询 / 长轮询 | ❌ | 延迟高、请求多、实现更复杂 |
| 一次性 JSON | ✅ 已有 | 就是现在的 `/ai/chat`，作为对照保留 |

### 1.2 为什么用 `SseEmitter` 而不是直接返回 `Flux`

你的项目是 **Servlet 栈**（Tomcat + 拦截器 + MyBatis 阻塞查询）。`SseEmitter` 是 Spring MVC 自带的异步返回值，不需要引入 WebFlux 的编程模型；而 `ChatClient.stream()` 本来返回 `Flux<String>`，我们只是把它“翻译”成 SSE 事件。

> 顺带一个好处：`SseEmitter` 会让请求进入 **async 模式**，Controller 返回后 Tomcat 线程就被释放了，模型慢慢吐字不占服务员（详见方案文档里“线程”那一节）。

## 二、接口契约

### 2.1 基本信息

| 项 | 值 |
|---|---|
| 方法 | `POST` |
| 路径 | `/ai/chat/stream`（前端走 `/api/ai/chat/stream`） |
| 鉴权 | `Authorization: Bearer <JWT>`，由现有 `AuthInterceptor` 拦截 |
| 请求体 | `application/json` |
| 响应 | `text/event-stream` |

### 2.2 请求

```http
POST /api/ai/chat/stream
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9....
Content-Type: application/json

{
  "content": "帮我找几本讲 Java 的书"
}
```

字段和 `/ai/chat` 完全一致：`content` 必填，trim 后 1–2000 字。

### 2.3 响应头

```http
HTTP/1.1 200 OK
Content-Type: text/event-stream;charset=UTF-8
Cache-Control: no-cache
X-Accel-Buffering: no
Transfer-Encoding: chunked
```

- `X-Accel-Buffering: no`：让 nginx 不要缓冲，否则“流式”会变成“等 30 秒一次性吐出来”；
- `Cache-Control: no-cache`：别让浏览器/代理缓存事件流。

### 2.4 事件协议（核心）

共 4 种事件，顺序固定：

| 事件 | 时机 | data 示例 | 前端动作 |
|---|---|---|---|
| `meta` | 流开始，立即发 | `{"model":"deepseek-flash"}` | 记下模型名，显示“正在思考” |
| `delta` | 每收到一个 chunk | `{"text":"馆藏里有"}` | 追加到当前气泡 |
| `done` | 正常结束 | `{"chars":128}` | 结束 loading，刷新按钮 |
| `error` | 中途失败 | `{"msg":"AI 服务暂时不可用"}` | 保留已收到内容 + 显示重试 |

一段完整的流：

```text
event: meta
data: {"model":"deepseek-flash"}

event: delta
data: {"text":"馆藏里"}

event: delta
data: {"text":"和 Java 相关的书有 3 本。"}

event: done
data: {"chars":18}
```

> **为什么 data 用 JSON 而不是纯文本？** 文本里只要有一个换行，SSE 就会把它拆成多行 `data:`，前端要自己再拼；JSON 序列化后只有一个物理行，最稳。

### 2.5 错误语义（和普通接口不一样）

| 阶段 | 表现 | 前端怎么处理 |
|---|---|---|
| 建立连接前（没 token、token 过期） | HTTP **401** + 普通 JSON | 清登录态，跳登录页 |
| 参数错误（空问题/超长） | Controller 直接抛 `BusinessException`，返回 **200 + code 0**（还没开始写流） | 走普通业务错误提示 |
| 流已经开始后（模型 401/429/超时） | **不能再改 HTTP 状态码**，只能发 `event: error` | 在气泡里显示错误，允许重试 |

⚠️ 这是流式接口最容易写错的地方：**一旦第一个字节写出去，HTTP 状态码就锁死了**。所以：
- 能提前校验的（登录、字数、开关）全部在返回 `SseEmitter` **之前**做；
- 上游错误只能走 `error` 事件。

### 2.6 和 `/ai/chat` 的关系

| 接口 | 返回 | 谁在用 |
|---|---|---|
| `POST /ai/chat` | `Result<AiChatVo>` | 页面开关关掉时；curl 调试；对照排障 |
| `POST /ai/chat/stream` | `text/event-stream` | 页面开关打开时 |

两个接口**共用同一套校验和提示词组装**，只是“怎么把结果交给浏览器”不同。不自动回退（方案 C 是手动开关），避免流式中途失败导致重复回答。

## 三、后端实现指导

### 3.1 Controller

```java
@RestController
@RequestMapping("/ai")
public class AiChatController {

    @Autowired
    private AiChatService aiChatService;

    @PostMapping(value = "/chat/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    public SseEmitter chatStream(@RequestBody AiChatRequest request,
                                 @RequestAttribute("loginUser") LoginUser loginUser,
                                 HttpServletResponse response) {
        // 这两个头必须在返回 SseEmitter 之前设置
        response.setHeader("X-Accel-Buffering", "no");
        response.setHeader("Cache-Control", "no-cache");
        return aiChatService.chatStream(request, loginUser);
    }
}
```

要点：

- `produces = MediaType.TEXT_EVENT_STREAM_VALUE` 必须写，否则 Spring 会按普通响应处理；
- 返回类型是 `SseEmitter`，不是 `Result`；
- 不要在这个方法里 `try/catch` 包住 `chatStream` 的全部逻辑又返回 `Result` —— 返回类型对不上。

### 3.2 Service（完整骨架）

```java
@Service
@Slf4j
public class AiChatService {

    @Autowired private AiProperties aiProperties;
    @Autowired private ChatClient chatClient;
    @Value("${spring.ai.deepseek.api-key:}") private String apiKey;

    public SseEmitter chatStream(AiChatRequest request, LoginUser loginUser) {
        if (!aiProperties.isEnabled()) {
            throw new BusinessException("AI 功能未开启");
        }

        String content = (request == null || request.getContent() == null)
                ? "" : request.getContent().trim();
        if (content.isEmpty()) {
            throw new BusinessException("请输入问题");
        }
        if (content.length() > 2000) {
            throw new BusinessException("单次提问请控制在 2000 字以内");
        }

        // ★ 超时用 emitter 自己的，别用默认 30s
        SseEmitter emitter = new SseEmitter(aiProperties.getStreamTimeoutMs());
        AtomicBoolean finished = new AtomicBoolean(false);
        AtomicReference<Disposable> subscription = new AtomicReference<>();
        StringBuilder buffer = new StringBuilder();

        send(emitter, "meta", Map.of("model", aiProperties.getModel()));

        // ---- 演示模式：不联网，也要走同一套事件 ----
        if (useMock()) {
            String text = "（演示模式，未调用真实模型）你问的是：「" + content + "」。";
            for (int i = 0; i < text.length(); i += 12) {
                send(emitter, "delta", Map.of(
                        "text", text.substring(i, Math.min(i + 12, text.length()))));
            }
            finished.set(true);
            send(emitter, "done", Map.of("chars", text.length()));
            emitter.complete();
            return emitter;
        }

        // ---- 真实调用 ----
        ChatClient.ChatClientRequestSpec spec = chatClient.prompt()
                .system(LibraryPrompt.CreaterSystemPrompt(loginUser))
                .user(content);

        Disposable disposable = spec.stream()
                .content()
                .subscribe(
                        chunk -> {
                            if (chunk == null || chunk.isEmpty()) return;
                            buffer.append(chunk);
                            send(emitter, "delta", Map.of("text", chunk));
                        },
                        error -> {
                            if (!finished.compareAndSet(false, true)) return;
                            log.warn("AI 流式失败", error);
                            send(emitter, "error", Map.of("msg", friendly(error)));
                            emitter.complete();
                        },
                        () -> {
                            if (!finished.compareAndSet(false, true)) return;
                            send(emitter, "done", Map.of("chars", buffer.length()));
                            emitter.complete();
                        });

        subscription.set(disposable);

        // 客户端断开 / 超时 / 出错：把订阅取消，别让模型继续烧 token
        emitter.onCompletion(() -> close(finished, subscription));
        emitter.onTimeout(() -> {
            close(finished, subscription);
            emitter.complete();
        });
        emitter.onError(e -> close(finished, subscription));

        return emitter;
    }

    private void close(AtomicBoolean finished, AtomicReference<Disposable> subscription) {
        if (!finished.compareAndSet(false, true)) return;
        Disposable d = subscription.get();
        if (d != null && !d.isDisposed()) {
            d.dispose();
        }
    }

    private void send(SseEmitter emitter, String event, Object data) {
        try {
            emitter.send(SseEmitter.event()
                    .name(event)
                    .data(data, MediaType.APPLICATION_JSON));
        } catch (IOException | IllegalStateException e) {
            // 浏览器关页面/断网都会走到这里，不要往上抛
            log.debug("SSE 发送失败（客户端可能已断开）：{}", e.getMessage());
        }
    }

    private String friendly(Throwable error) {
        String raw = error.getMessage() == null ? "" : error.getMessage();
        String lower = raw.toLowerCase();
        if (raw.contains("401") || lower.contains("unauthorized")) {
            return "AI 服务鉴权失败，请检查 API Key 是否配置正确";
        }
        if (raw.contains("429") || lower.contains("rate limit")) {
            return "提问太频繁了，请稍后再试";
        }
        if (lower.contains("timeout")) {
            return "AI 响应超时，请重试";
        }
        return "AI 服务暂时不可用，请稍后再试";
    }
}
```

需要的 import：

```java
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.http.MediaType;
import org.springframework.web.servlet.mvc.method.annotation.SseEmitter;
import reactor.core.Disposable;
import java.io.IOException;
import java.util.Map;
import java.util.concurrent.atomic.AtomicBoolean;
import java.util.concurrent.atomic.AtomicReference;
```

### 3.3 三个关键点

1. **`finished` 是闸门**：正常结束、出错、断开、超时，谁先抢到 `compareAndSet(false, true)` 谁负责收尾，避免重复 `complete()` 抛 `IllegalStateException`。
2. **`onCompletion` 在正常结束后也会触发**：所以 `close()` 里必须先判断 `finished`，否则会把已经结束的流 dispose 一遍（虽然无害，但逻辑混乱）。
3. **`send` 必须吞异常**：客户端断开时这里会抛 `IOException`，抛出去只会污染日志，不会让前端多收到什么。

### 3.4 超时配置（你现在的 yml 是错的）

必须放在 `spring.mvc` 下，**不能缩进在 `spring.ai` 里面**：

```yaml
spring:
  mvc:
    async:
      request-timeout: 200000
```

你当前的 yml 里 `mvc` 还在 `spring.ai` 下面，等于没配。SSE 超过默认异步超时会断流，先把这段挪出来。

### 3.5 不要做的事

| 不要 | 原因 |
|---|---|
| 把 `chatStream` 包进 `@Transactional` | 事务/连接会被占住几分钟 |
| 在 `delta` 里写数据库 | 每个 chunk 一条 SQL，纯属自杀 |
| 在 Controller 里 `catch` 后返回 `Result` | 返回类型不匹配，且流已经开始了 |
| 用 `emitter.send(String)` 发带换行的文本 | 破坏 SSE 的 `data:` 分行协议 |
| 忘记 `dispose()` | 用户关了页面，模型还在计费 |

## 四、前端实现指导（方案 C）

### 4.1 `api/ai.js` 增加 `streamChat`

```js
import { TOKEN_KEY } from '@/utils/request'

export async function streamChat({ content, signal, onMeta, onDelta, onDone }) {
  const token = localStorage.getItem(TOKEN_KEY)
  const resp = await fetch('/api/ai/chat/stream', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      ...(token ? { Authorization: `Bearer ${token}` } : {})
    },
    body: JSON.stringify({ content }),
    signal
  })

  if (resp.status === 401) {
    const e = new Error('登录已过期，请重新登录')
    e.code = 401
    throw e
  }
  if (!resp.ok) throw new Error(`AI 服务异常（HTTP ${resp.status}）`)
  if (!resp.body) throw new Error('当前浏览器不支持流式响应')

  const reader = resp.body.getReader()
  const decoder = new TextDecoder('utf-8')
  let buffer = ''

  const handleBlock = (block) => {
    let event = 'message'
    const data = []
    for (const line of block.split('\n')) {
      const clean = line.replace(/\r$/, '')
      if (clean.startsWith('event:')) event = clean.slice(6).trim()
      else if (clean.startsWith('data:')) data.push(clean.slice(5).trim())
    }
    if (!data.length) return

    let payload = null
    try { payload = JSON.parse(data.join('\n')) } catch { payload = null }

    if (event === 'meta') onMeta?.(payload)
    else if (event === 'delta') onDelta?.(payload?.text || '')
    else if (event === 'done') onDone?.(payload)
    else if (event === 'error') throw new Error(payload?.msg || 'AI 出错')
  }

  while (true) {
    const { done, value } = await reader.read()
    if (done) break
    buffer += decoder.decode(value, { stream: true })

    let sep
    while ((sep = buffer.indexOf('\n\n')) >= 0) {
      const block = buffer.slice(0, sep)
      buffer = buffer.slice(sep + 2)
      handleBlock(block)
    }
  }
}
```

### 4.2 页面里的开关（方案 C）

`AiChatView.vue` 顶部加一个常量：

```js
// 后端 SSE 就绪后改成 true；出问题改回 false 立刻走 JSON 接口
const USE_STREAM = false
```

`requestAnswer` 里二选一：

```js
if (USE_STREAM) {
  controller = new AbortController()
  await streamChat({
    content: question,
    signal: controller.signal,
    onMeta: (m) => { assistant.meta = m?.model || '' },
    onDelta: (text) => { assistant.content += text; scheduleScroll() }
  })
} else {
  const data = await chat(question)
  assistant.content = data?.content || '（没有返回内容）'
  assistant.meta = buildMeta(data)
}
```

### 4.3 停止生成

`AbortController` 一 abort，浏览器会断开 fetch，服务端 `onCompletion` 触发 `dispose()`，模型停止计费。

```js
function stop() {
  controller?.abort()
}
```

界面只在流式模式下显示「停止生成」按钮：

```html
<el-button v-if="USE_STREAM && sending" @click="stop">停止生成</el-button>
<el-button v-else type="primary" :loading="sending" :disabled="!canSend" @click="send">发送</el-button>
```

### 4.4 为什么不用 EventSource / axios

| 方案 | 问题 |
|---|---|
| `EventSource` | 只能 GET，**不能带 `Authorization` 头**；把 token 拼进 URL 会进日志/历史 |
| axios | 浏览器端拿不到“边下边读”的增量，`onDownloadProgress` 在部分环境下也不可靠 |
| `fetch` + `ReadableStream` | ✅ 可以带 header、可以 POST、可以 abort、可以手动解析帧 |

## 五、nginx（生产环境）

```nginx
location ^~ /api/ai/chat/stream {
    proxy_pass http://127.0.0.1:8081;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header Connection '';
    proxy_buffering off;       # 关键：不缓冲
    proxy_cache off;
    gzip off;                  # 关键：不压缩，否则前端拿不到增量
    proxy_read_timeout 300s;
    chunked_transfer_encoding on;
}
```

这一段要放在通用 `location /api/` **之前**（`^~` 前缀匹配优先），否则会被通用规则先接走。

## 六、联调验收清单

| # | 操作 | 预期 |
|---|---|---|
| 1 | `curl -N` 调接口 | 终端里逐条出现 `event:`，不是等半天一次性出现 |
| 2 | 浏览器 Network → 该请求 | Type 是 `eventsource`，Response 持续增长 |
| 3 | 页面发问 | 气泡逐字增长，首字 < 1s |
| 4 | 点「停止生成」 | 立刻停；后端日志出现 dispose 相关 debug，不再有新的 delta |
| 5 | 关掉标签页 | 后端最终停止输出（日志无新 chunk） |
| 6 | 不配 key（mock） | 也能逐字出现演示文案，末尾 `done` |
| 7 | 把 key 改错 | 气泡里出现「鉴权失败」，不是白屏/500 |
| 8 | 回答超过 3 分钟 | 触发超时，收到 `error` 或连接结束，页面不卡死 |
| 9 | 中文/emoji | 不乱码（`TextDecoder('utf-8')`） |
| 10 | 开关改回 `false` | 自动走 `/ai/chat`，功能不变 |

## 七、踩坑清单

| # | 现象 | 原因 | 处理 |
|---|---|---|---|
| 1 | 等全部生成完才一次性显示 | nginx 缓冲 / gzip | `X-Accel-Buffering: no` + `proxy_buffering off` + `gzip off` |
| 2 | 30 秒后断流 | `spring.mvc.async.request-timeout` 没生效（缩进错了） | 挪到 `spring:` 下，或给 `SseEmitter` 传超时 |
| 3 | 401 变成“服务器异常” | 异常冒到全局处理器 | 流开始前校验；流开始后走 `error` 事件 |
| 4 | 用户关了页面，token 还在烧 | 没 `dispose()` | `onCompletion/onTimeout/onError` 里取消订阅 |
| 5 | 重复 `complete()` 报 `IllegalStateException` | 多处收尾 | `finished` 原子闸门 |
| 6 | `delta` 里出现 JSON 被截断 | 一次 read 读到半帧 | 用 `buffer` 累积，按 `\n\n` 切帧 |
| 7 | 中文乱码 | 没按 UTF-8 解 | `TextDecoder('utf-8')`；Spring 默认 UTF-8 |
| 8 | 前端收到 `event:message` | 服务端没写 `name(...)` | `SseEmitter.event().name("delta")` |
| 9 | 流式正常但页面出现两条回答 | 流结束后又调了非流式接口 | 开关二选一，别两个都调 |
| 10 | 点停止后仍收到 delta | 只 abort 了前端，没 dispose 后端 | 后端 `onCompletion` 里 dispose |

## 八、P2 预留

| 版本 | 变化 | 对 SSE 的影响 |
|---|---|---|
| P2 会话/历史 | 请求体加 `conversationId`，流开始前落库 | `meta` 事件里多返回 `conversationId/messageId`，协议向后兼容 |
| P3 工具调用 | 模型可能先调工具再回答 | 可加 `event: tool`（“正在查馆藏…”），前端渲染为状态行 |
| P4 额度 | 流开始前校验 | 超限时直接返回 200 + code 0（还没开始写流） |

> 协议设计成“先 meta、再 delta、最后 done/error”，就是为了以后能无痛插入新事件类型——前端只认自己认识的，不认识的忽略即可。
