## 〇、2.0 到底要做什么（先看这一节）

一句话：**加登录，并且让管理员和普通用户看到的东西不一样。**

> **你的要求原文**：用户登录时和管理员登录时界面不一样；普通用户不能删除图书、不能修改状态、不能新增图书；**2.0 里普通用户只有「查询」和「查看详情」两个功能**。

### 0.2 我替你定的 4 个决策（不同意就说，都好改）

| # | 决策 | 理由 | 想改的话 |
|---|---|---|---|
| 1 | **图书查询也要求登录**（游客不能浏览） | 你说了"2.0 做用户和管理员的登录验证"，说明登录是入口。而且图书管理系统的馆藏信息一般不给外人看 | 在拦截器里加 `excludePathPatterns("/books", "/books/*", "/categories")` 就能开放游客浏览 |

## 一、通用约定补充（在 1.0 的基础上新增）

### 1.1 请求头带 token

登录成功后，**之后每个请求都要带上这个头**：

```
Authorization: Bearer eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1NiJ9.eyJ1c2VySWQiOjEs...
```

- 前缀固定是 `Bearer `（后面一个空格），这是行业标准写法
- 后端解析时：`header.substring(7)` 把 `Bearer ` 切掉
- **前端已经写好了**：`src/utils/request.js` 的请求拦截器会自动从 localStorage 取 token 塞进去，你写业务代码时不用管

### 1.2 HTTP 状态码（在 1.0 的三种基础上新增 403）

| HTTP | 场景 | 返回体 | 前端行为 |
|---|---|---|---|
| `200` | 成功，**以及业务失败**（如"用户名或密码错误"） | `{code:1/0, msg, data}` | 成功走逻辑，失败弹 msg |
| `401` | **没登录 / token 无效 / token 过期 / 账号被禁用** | `{code:0, msg:"未登录或登录已过期", data:null}` | **清 token + 跳登录页** |
| `403` | 登录了，但**角色不够**（普通用户去调管理员接口） | `{code:0, msg:"没有操作权限", data:null}` | **只弹提示，不跳转** |
| `500` | 服务器内部异常 | `{code:0, msg:"服务器异常，请联系管理员", data:null}` | 弹提示 |

> ⚠️ **401 和 403 的区别一定要分清**，这是 2.0 最容易做错的地方：
> - `401` = 「我不知道你是谁」→ 去登录
> - `403` = 「我知道你是谁，但你不能干这个」→ 你已经登录了，跳登录页毫无意义

## 三、接口详情

### 1. 登录

| 项 | 值 |
|---|---|
| 请求方法 | `POST` |
| 后端路径 | `/auth/login` |
| 前端请求 | `/api/auth/login` |
| 请求头 | `Content-Type: application/json` |
| **是否需要登录** | ❌ **不需要（这是唯一放行的接口）** |

**前端向后端请求的数据**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `username` | String | ✅ | 登录名 |
| `password` | String | ✅ | **明文密码**（走 HTTPS 才安全；本地开发无所谓） |

```json
{ "username": "admin", "password": "123456" }
```

**你希望我返回的数据**

```json
{
  "code": 1,
  "msg": "登录成功",
  "data": {
    "token": "eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1NiJ9.eyJ1c2VySWQiOjEsInVzZXJuYW1lIjoiYWRtaW4iLCJyb2xlIjoiQURNSU4iLCJpYXQiOjE3OTIwMDAwMDAsImV4cCI6MTc5MjAwNzIwMH0.xxxxx",
    "user": {
      "id": 1,
      "username": "admin",
      "realName": "系统管理员",
      "role": "ADMIN",
      "avatar": null
    }
  }
}
```

> ⚠️ **`user` 对象里绝对不要返回 `password`**，哪怕是哈希也不要。
> 做法：`UserVO` 里压根不定义 password 字段，而不是"定义了但在 Controller 里 setNull"。

**可能的错误返回**（都是 HTTP 200 + code:0）

| 场景 | msg |
|---|---|
| 用户名不存在 | `用户名或密码错误` |
| 密码错 | `用户名或密码错误`（**和上面故意用同一句**） |
| 账号被禁用 | `该账号已被禁用，请联系管理员` |
| 用户名为空 | `用户名不能为空` |

> 🔒 **为什么"用户不存在"和"密码错误"要给同一句提示？**
> 如果分开提示，攻击者就能拿一堆用户名去试，**靠报错文案判断哪些用户名是真实存在的**（这叫用户名枚举）。
> 统一成一句话，就什么都试不出来。这是登录接口最基本的安全习惯。

---

### 2. 获取当前登录用户

**用途**：前端刷新页面后，localStorage 里只有 token、没有用户信息，靠这个接口把用户信息取回来（否则刷新后菜单和按钮会闪一下或者直接错乱）。

| 项 | 值 |
|---|---|
| 请求方法 | `GET` |
| 后端路径 | `/auth/me` |
| 前端请求 | `/api/auth/me` |
| 需要登录 | ✅ |

**前端向后端请求的数据**：无（只靠 `Authorization` 头）

**你希望我返回的数据**（结构就是登录返回里的 `user` 那段，**不带 token**）

```json
{
  "code": 1,
  "msg": "success",
  "data": {
    "id": 1,
    "username": "admin",
    "realName": "系统管理员",
    "role": "ADMIN",
    "avatar": null
  }
}
```

**错误**：没带 token / token 过期 → **HTTP 401** + `{"code":0,"msg":"未登录或登录已过期","data":null}`

> 前端拿到 401 会自动跳登录页，你后端只要老实返回 401 就行。

### 3. 退出登录

| 项 | 值 |
|---|---|
| 请求方法 | `POST` |
| 后端路径 | `/auth/logout` |
| 需要登录 | ✅ |

**你希望我返回的数据**

```json
{ "code": 1, "msg": "已退出登录", "data": null }
```

> **JWT 是无状态的，服务端没有"登录状态"可清**，真正的退出动作是**前端把 localStorage 里的 token 删掉**。
> 这个接口存在的意义是：留个位置，将来要做「token 黑名单 / 强制下线」时有地方下手。
> **1.0 实现方式**：后端直接 `return new Result().success("已退出登录", null)` 就行，一行代码。

### 4. 修改自己的密码

| 项 | 值 |
|---|---|
| 请求方法 | `PUT` |
| 后端路径 | `/auth/password` |
| 需要登录 | ✅（**只能改自己的，改别人的走 `/users/{id}/password`**） |

**前端向后端请求的数据**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `oldPassword` | String | ✅ | 原密码 |
| `newPassword` | String | ✅ | 新密码，长度 6~20 |

```json
{ "oldPassword": "123456", "newPassword": "abc123456" }
```

> ⚠️ **请求体里不要传 userId！** 当前用户是谁由 token 决定（从 `Authorization` 头解析），
> 如果让前端传 userId，那任何人改一下这个数字就能改别人的密码 —— 这是**水平越权漏洞**。

**你希望我返回的数据**

```json
{ "code": 1, "msg": "密码修改成功", "data": null }
```

**可能的错误返回**

| 场景 | msg |
|---|---|
| 原密码错 | `原密码不正确` |
| 新密码太短 | `新密码长度至少 6 位` |
| 新旧密码相同 | `新密码不能和原密码相同` |

**后端要点**：用 `BCrypt.checkpw(明文, 库里的哈希)` 校验旧密码，用 `BCrypt.hashpw(新密码, BCrypt.gensalt())` 存新密码。

### 5. 给 1.0 的图书接口加权限（★ 改造，不新增接口）

**这是 2.0 最核心的改动**：1.0 里那 8 个图书接口现在要按角色放行。

| 原有接口 | 改造后 |
|---|---|
| `GET /categories` | 登录就能用 |
| `GET /books` | 登录就能用 |
| `GET /books/{id}` | 登录就能用 |
| `POST /books` | **要 ADMIN** |
| `PUT /books/{id}` | **要 ADMIN** |
| `DELETE /books/{id}` | **要 ADMIN** |
| `DELETE /books/batch` | **要 ADMIN** |
| `PATCH /books/{id}/status` | **要 ADMIN** |
| `POST /files/upload` | **要 ADMIN** |

**怎么实现最省事？—— 自定义一个注解，标在方法上**（下面第五节给了完整代码）

```java
@RequireAdmin                       // ← 就加这一行
@PostMapping("/books")
public Result AddBook(@RequestBody BookSaveDto bookSaveDto) { ... }
```

**⚠️ 这里有个坑必须提醒你**：不要企图用「路径通配符」来拦管理员接口。

Spring 的 `addPathPatterns("/books/*")` **不带 HTTP 方法**，它会同时匹配：
- `PUT /books/1`（要 ADMIN ✅）
- `GET /books/1`（普通用户的「查看详情」，**绝对不能拦** ❌）

一旦这么配，普通用户点「详情」就会被 403，而且报错信息看起来完全不合理，很难查。
**用 `@RequireAdmin` 注解按方法精确控制**，就没有这个歧义。

### 7. 新增用户（管理员）

**前端向后端请求的数据**

| 字段 | 类型 | 必填 | 校验 | 说明 |
|---|---|---|---|---|

```json
{
  "username": "wangwu",
  "password": "123456",
  "realName": "王五",
  "phone": "13800000004",

  "status": 1
}
```

**你希望我返回的数据**：`{ "code": 1, "msg": "新增成功", "data": null }`

```java
// 存之前一定要加密！绝对不能把明文塞进数据库
user.setPassword(BCrypt.hashpw(dto.getPassword(), BCrypt.gensalt()));
```

|---|---|

| 后端路径 | `/users/{id}` |

| 字段 | 类型 | 说明 |
|---|---|---|
| `realName` | String | 姓名 |
| `phone` | String | 手机号 |
| `email` | String | 邮箱 |
| `role` | String | 角色 |
| `status` | Integer | 状态 |

```json
{ "realName": "王五（改名后）", "phone": "13800000009", "role": "USER", "status": 1 }
```

## 四、类定义（要建哪些类、每个类什么属性）

### 4.1 `SysUser`（实体，对应 `sys_user` 表）

| 属性 | Java 类型 | 对应列 | 说明 |
|---|---|---|---|

### 5.1 `JwtUtil`（用 jjwt 0.12.6）

> **为什么用 jjwt？** 它是 JWT 领域事实上的标准库，API 最直观（`Jwts.builder().claim(...).signWith(...)`），
> 而且**过期校验和 claim 类型转换都是自动的**，不像 hutool 那样要手工补两步。
>
> **代价要知道**：`jjwt-jackson` 依赖 **Jackson 2**，而 Spring Boot 4 用的是 **Jackson 3**（`tools.jackson`），
> 所以项目里会同时存在两个 Jackson。两者包名不同、**实测不冲突**，代价只是多约 2MB 重复功能。
>
> 密码哈希仍然用 hutool 的 BCrypt（不再额外引 spring-security-crypto）。

**在 `pom.xml` 加 4 个依赖** —— ⚠️ 0.12.x **必须拆成三个 artifact**，不能像老版本那样只引一个 `jjwt`：

```xml
<!-- 密码哈希：hutool 的 BCrypt -->
<dependency>
    <groupId>cn.hutool</groupId>
    <artifactId>hutool-all</artifactId>
    <version>5.8.27</version>
</dependency>

<!-- JWT：jjwt 0.12.6，三个 artifact 缺一不可 -->
<dependency>
    <groupId>io.jsonwebtoken</groupId>
    <artifactId>jjwt-api</artifactId>
    <version>0.12.6</version>
</dependency>
<dependency>
    <groupId>io.jsonwebtoken</groupId>
    <artifactId>jjwt-impl</artifactId>
    <version>0.12.6</version>
    <scope>runtime</scope>
</dependency>
<dependency>
    <groupId>io.jsonwebtoken</groupId>
    <artifactId>jjwt-jackson</artifactId>
    <version>0.12.6</version>
    <scope>runtime</scope>
</dependency>
```

> ⚠️ **千万别用 0.9.1**（很多老教程用的就是它）：它在 **JDK 11+ 上会因 `javax.xml.bind` 被移出 JDK 而报错**，
> 而且 `signWith(SignatureAlgorithm, String)` 里的密钥必须事先 Base64 编码，直接传明文会抛 `WeakKeyException`。

```java
package org.libaray_manager_system.utils;

import io.jsonwebtoken.Claims;
import io.jsonwebtoken.JwtException;
import io.jsonwebtoken.Jwts;
import io.jsonwebtoken.security.Keys;

import javax.crypto.SecretKey;
import java.nio.charset.StandardCharsets;
import java.util.Date;

public class JwtUtil {

    /**
     * 默认签名密钥（占位符，课程/本地演示用）
     * ⚠️ 长度必须 >= 32 字节（HS256 的下限），否则启动时会抛异常并提示当前字节数。
     * ⚠️ 生效顺序：环境变量 JWT_SECRET > JVM 参数 -Djwt.secret > 下面这个默认值。
     *    真实部署务必设置 JWT_SECRET，别把生产密钥写死在代码里。
     */
    private static final String DEFAULT_SECRET = "library-manager-2.0-secret-key-change-me-in-production";
    private static final String SECRET = resolveSecret();   // 环境变量 > JVM 参数 > 默认值

    private static final SecretKey KEY = buildKey(SECRET);

    /** 有效期：2 小时 */
    private static final long EXPIRE_MILLIS = 2 * 60 * 60 * 1000L;

    /** 生成 token */
    public static String createToken(Long userId, String username, String role) {
        return Jwts.builder()
                .claim("userId", userId)
                .claim("username", username)
                .claim("role", role)
                .issuedAt(new Date())
                .expiration(new Date(System.currentTimeMillis() + EXPIRE_MILLIS))
                // 0.12.x 只传密钥，算法由密钥长度自动推断（见下方实测结论）
                .signWith(KEY)
                .compact();
    }

    /**
     * 解析并校验 token（验签 + 验过期，一次做完）
     *
     * @return Claims；任何问题（格式错 / 签名被改 / 已过期）都返回 null，
     *         由调用方（拦截器）统一处理成 HTTP 401
     *
     * 下面这个 catch 覆盖了 jjwt 会抛的全部异常，它们都继承自 JwtException：
     *   ExpiredJwtException     已过期
     *   SignatureException      签名不匹配（token 被改过）
     *   MalformedJwtException   格式不对
     *   UnsupportedJwtException 算法不支持
     */
    public static Claims parseAndVerify(String token) {
        if (token == null || token.isBlank()) {
            return null;
        }
        try {
            return Jwts.parser()
                    // 0.12.x 是 verifyWith(SecretKey)；0.11 及以前叫 setSigningKey(...)
                    .verifyWith(KEY)
                    .build()
                    .parseSignedClaims(token)   // ← 过期校验就在这一步里，自动的
                    .getPayload();
        } catch (JwtException | IllegalArgumentException e) {
            return null;
        }
    }

    /**
     * 取 userId
     *
     * 用 Number 再 longValue()，是因为 JSON 里的整数可能被反序列化成 Integer 或 Long，
     * 拿 Number 兜住两种情况都不会出错。
     */
    public static Long getUserId(Claims claims) {
        Number n = claims.get("userId", Number.class);
        return n == null ? null : n.longValue();
    }

    public static String getUsername(Claims claims) {
        return claims.get("username", String.class);
    }

    public static String getRole(Claims claims) {
        return claims.get("role", String.class);
    }
}
```

> **实测结论**（我在本机真跑过一遍，不是照抄文档）：
> - 正常生成 / 解析 ✅
> - 篡改一个字符、换密钥签、乱码串、空串、null → **全部返回 `null`** ✅
> - **已过期的 token → 返回 `null`** ✅ —— 证实 jjwt 的 `parseSignedClaims` **把过期一起校验了**，
>   **不需要**像 hutool 那样再手工调一次 `validateDate()`
> - `claims.get("userId", Number.class)` 取到 `1`，转出来是 `Long` ✅
> - ⚠️ **算法是按密钥长度自动选的**：上面那个 53 字节密钥，jjwt 选的是 **HS384**（不是 HS256）。
>   规则是 256~383 bit→HS256、384~511 bit→HS384、512 bit+→HS512，更安全；
>   想锁死 HS256 就写 `.signWith(KEY, Jwts.SIG.HS256)`

### 5.2 登录拦截器（一个就够，同时管登录和角色）

```java
package org.libaray_manager_system.interceptor;

import io.jsonwebtoken.Claims;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import org.libaray_manager_system.annotation.RequireAdmin;
import org.libaray_manager_system.mapper.UserMapper;
import org.libaray_manager_system.pojo.LoginUser;
import org.libaray_manager_system.pojo.entity.SysUser;
import org.libaray_manager_system.utils.JwtUtil;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Component;
import org.springframework.web.method.HandlerMethod;
import org.springframework.web.servlet.HandlerInterceptor;

@Component
public class AuthInterceptor implements HandlerInterceptor {

    @Autowired
    private UserMapper userMapper;

    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler)
            throws Exception {

        // 静态资源等非 Controller 方法直接放行
        if (!(handler instanceof HandlerMethod handlerMethod)) {
            return true;
        }

        // ---------- 第 1 步：校验登录 ----------
        String header = request.getHeader("Authorization");
        String token = (header != null && header.startsWith("Bearer "))
                ? header.substring(7)
                : header;

        Claims claims = JwtUtil.parseAndVerify(token);
        if (claims == null) {
            return reject(response, 401, "未登录或登录已过期");
        }

        // 再查一次库：token 没过期 ≠ 账号还能用（可能刚被管理员禁用/删除了）
        SysUser user = userMapper.GetEntityByUsername(JwtUtil.getUsername(claims));
        if (user == null || user.getStatus() == 0) {
            return reject(response, 401, "账号不存在或已被禁用");
        }

        // 把当前用户放进 request，Controller 用 @RequestAttribute("loginUser") 取
        LoginUser loginUser = new LoginUser(
                user.getId(), user.getUsername(), user.getRealName(), user.getRole());
        request.setAttribute("loginUser", loginUser);

        // ---------- 第 2 步：校验角色 ----------
        // 只有标了 @RequireAdmin 的方法才需要管理员
        if (handlerMethod.getMethodAnnotation(RequireAdmin.class) != null && !loginUser.isAdmin()) {
            return reject(response, 403, "没有操作权限");
        }

        return true;
    }

    /** 按项目约定输出 {code,msg,data}，并设置对应的 HTTP 状态码 */
    private boolean reject(HttpServletResponse response, int status, String msg) throws Exception {
        response.setStatus(status);
        response.setContentType("application/json;charset=UTF-8");
        response.getWriter().write(
                "{\"code\":0,\"msg\":\"" + msg + "\",\"data\":null}");
        return false;
    }
}
```

> ⚠️ **`ObjectMapper` 的包名**：Spring Boot 4 用的是 **Jackson 3**，包名从 `com.fasterxml.jackson.databind`
> 变成了 `tools.jackson.databind`。上面的 `reject()` 我故意**手写 JSON 字符串**，
> 就是为了避开这个坑 —— 拦截器里只用了一句固定格式的返回，没必要引入 ObjectMapper。

### 5.3 注册拦截器

```java
package org.libaray_manager_system.config;

import org.libaray_manager_system.interceptor.AuthInterceptor;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.context.annotation.Configuration;
import org.springframework.web.servlet.config.annotation.InterceptorRegistry;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

@Configuration
public class WebConfig implements WebMvcConfigurer {

    @Autowired
    private AuthInterceptor authInterceptor;

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(authInterceptor)
                .addPathPatterns("/**")
                // 登录接口必须放行，否则没人能拿到 token（死锁）
                .excludePathPatterns("/auth/login");
    }
}
```

> **注意**：这里**没有**按路径去拦管理员接口 —— 那正是 3.5 节说的坑。
> 角色控制全部由方法上的 `@RequireAdmin` 注解决定。

### 6.3 登录流程（前端视角）

```
打开任意页面
  → 路由守卫检查 localStorage 有没有 token
      ├─ 没有 → 跳 /login
      └─ 有   → 放行；如果是刷新，顺便调 /auth/me 把用户信息取回来
                （取回来之前先不渲染，避免菜单先显示"管理员"再变成"读者"闪一下）

登录页提交 → POST /auth/login
  → 成功：把 token + user 存进 localStorage → 跳 /books
  → 失败：弹 msg（"用户名或密码错误"）

任意请求返回 401 → 清 token → 跳 /login（提示"登录已过期，请重新登录"）
任意请求返回 403 → 只弹"没有操作权限"，**不跳转**
```
