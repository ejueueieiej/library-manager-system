# 5.0 AI 对话 · 接口文档（第一步：单轮问答）

> 这份文档对应 **P0 的第一个可用版本**：用户问一句，AI 答一句。
> 不保存会话、不带上下文、不做流式 —— 这些都留到 P1/P2。
>
> 前端页面已经按本文档实现完成，文件清单见第五节；后端照第四节的清单实现即可联调。

---

## 〇、这一步的范围

| 做 | 不做（后续版本） |
|---|---|
| 一次提问、一次完整回答 | 多轮上下文（P1） |
| 任意登录用户可用（JWT 鉴权） | SSE 流式输出（P1） |
| 演示模式（没配 key 也能跑） | 会话列表 / 历史消息（P2） |
| 前端把消息存在**当前页面内存** | 查馆藏、查借阅的工具调用（P3） |
| 返回模型名、耗时、token 用量 | 多模型切换、RAG |

⚠️ **重要预期**：本版**不写数据库**。刷新页面 = 对话清空。这是刻意的最小实现，不是 bug。

## 一、通用约定

| 项 | 约定 |
|---|---|
| 后端地址 | `http://localhost:8081` |
| 前端前缀 | `/api`（Vite 代理剥掉前缀后转发到后端，开发/生产行为一致） |
| 鉴权 | `Authorization: Bearer <JWT>`，`/ai/**` 被现有 `AuthInterceptor` 的 `/**` 规则覆盖，**不需要改 WebConfig** |
| 返回结构 | `{ code, msg, data }`，`code=1` 成功，`code=0` 业务失败（HTTP 仍为 200） |
| 编码 | UTF-8 |
| 请求体 | `application/json` |
| 建议超时 | **60 秒**。axios 实例默认 10 秒，模型生成经常超过，必须单独放大 |

## 二、接口：`POST /ai/chat`

### 2.1 作用

把用户的一句话发给模型，返回一段完整回答。单轮，不带历史。

### 2.2 请求

```http
POST /api/ai/chat
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9....
Content-Type: application/json

{
  "content": "帮我找几本讲 Java 的书"
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `content` | string | 是 | 用户问题。**trim 后长度 1–2000**，超长/为空返回业务错误 |

### 2.3 成功响应

```json
{
  "code": 1,
  "msg": "success",
  "data": {
    "content": "馆藏里和 Java 相关的书有……",
    "model": "deepseek-flash",
    "promptTokens": 128,
    "completionTokens": 96,
    "elapsedMs": 1520,
    "mock": false
  }
}
```

| 字段 | 类型 | 可能为 null | 说明 |
|---|---|---|---|
| `content` | string | 否 | 回答正文（纯文本，可能带换行和简单 Markdown） |
| `model` | string | 否 | 实际使用的模型名，来自 `library.ai.model` |
| `promptTokens` | int | 是 | 输入 token；流式/演示模式下可能没有 |
| `completionTokens` | int | 是 | 输出 token |
| `elapsedMs` | long | 否 | 服务端从发请求到收完的耗时（毫秒） |
| `mock` | boolean | 否 | `true` = 演示模式，没有真正调用模型 |

### 2.4 业务失败（HTTP 200，`code=0`）

```json
{
  "code": 0,
  "msg": "单次提问请控制在 2000 字以内"
}
```

| `msg` | 触发条件 |
|---|---|
| 请输入问题 | `content` 为空白 |
| 单次提问请控制在 2000 字以内 | trim 后超过 2000 字符 |
| AI 功能未开启 | `library.ai.enabled=false` |
| AI 服务鉴权失败，请检查 DEEPSEEK_API_KEY 是否配置正确 | key 无效 / 未配置且未进 mock |
| AI 账户余额不足，请联系管理员 | 供应商返回欠费 |
| 提问太频繁了，休息一下再试 | 供应商限流（429） |
| AI 响应超时，请重试 | 上游超时 |
| AI 服务暂时不可用，请稍后再试 | 其他上游错误 |

> HTTP 层错误只有两种：**401**（没带/过期 token，返回 `{code:0,msg:"..."}`）和 **500**（真正的程序 bug）。
> 业务失败一律 200，这是项目现有约定（见 `GlobalExceptionHandler` 的注释）。

### 2.5 演示模式

没有配 `DEEPSEEK_API_KEY`（yml 里仍是 `sk-local-placeholder`）或 `library.ai.mock=true` 时：

- 不会发起任何网络请求；
- 返回 `mock: true`，`content` 是一段说明文字（复述用户问题 + 提示配 key）；
- 前端照常展示，链路完全可演示。

## 三、curl 自测

```bash
# 1) 先登录拿 token
curl -X POST http://localhost:8081/auth/login ^
  -H "Content-Type: application/json" ^
  -d "{\"username\":\"zhangsan\",\"password\":\"123456\"}"

# 2) 用 token 调 AI
curl -X POST http://localhost:8081/ai/chat ^
  -H "Content-Type: application/json" ^
  -H "Authorization: Bearer 把上一步的token贴这里" ^
  -d "{\"content\":\"帮我找几本讲 Java 的书\"}"
```

> Windows 的 `cmd` 用 `^` 续行；PowerShell 请改用 `Invoke-RestMethod`，或把 JSON 写进文件后用 `--data-binary @body.json`。
> 最省事的还是直接用前端页面发，或者项目 `docs/api` 下那套调试页面。

## 四、后端最小实现清单（不建表、不做历史）

和完整方案相比，这一步只需要这些：

| # | 文件 | 作用 |
|---|---|---|
| 1 | `pom.xml` | 加 `spring-ai-bom` + `spring-ai-starter-model-deepseek` |
| 2 | `application.yml` | `spring.ai.deepseek.*` + `library.ai.*` |
| 3 | `ai/config/AiProperties.java` | `library.ai.*` 配置 |
| 4 | `ai/config/AiConfig.java` | 构建 `ChatClient`（系统提示词 + 日志 advisor） |
| 5 | `ai/prompt/LibraryPrompt.java` | 系统提示词 |
| 6 | `ai/dto/AiChatRequest.java` | `{ content }` |
| 7 | `ai/dto/AiChatVo.java` | 上面的响应 `data` |
| 8 | `ai/service/AiChatService.java` + `impl/AiChatServiceImpl.java` | 校验 → mock 分支 → 调模型 → 组装 VO |
| 9 | `ai/controller/AiChatController.java` | `POST /ai/chat` |

**不需要**：数据库表、Mapper、会话 Service、SSE、工具类、限流（限流可以等 P4）。

### 4.1 配置

```yaml
spring:
  ai:
    deepseek:
      api-key: ${DEEPSEEK_API_KEY:sk-local-placeholder}
      base-url: ${DEEPSEEK_BASE_URL:https://api.deepseek.com}
      chat:
        model: ${DEEPSEEK_MODEL:deepseek-flash}
        temperature: 0.7
        max-tokens: 1024

library:
  ai:
    enabled: true
    mock: false
    model: ${DEEPSEEK_MODEL:deepseek-flash}
```

### 4.2 Service 的核心只有十几行

```java
@Override
public AiChatVo Chat(AiChatRequest req, LoginUser user) {
    if (!aiProperties.isEnabled()) {
        throw new BusinessException("AI 功能未开启");
    }
    String content = req == null || req.getContent() == null ? "" : req.getContent().trim();
    if (content.isEmpty()) {
        throw new BusinessException("请输入问题");
    }
    if (content.length() > 2000) {
        throw new BusinessException("单次提问请控制在 2000 字以内");
    }

    long start = System.currentTimeMillis();

    // 演示模式：不联网
    if (useMock()) {
        String text = "（演示模式，未调用真实模型）你问的是：「" + content + "」。"
                + "配置 DEEPSEEK_API_KEY 后重启即可获得真实回答。";
        return new AiChatVo(text, aiProperties.getModel(), null, null,
                System.currentTimeMillis() - start, true);
    }

    ChatResponse response = chatClient.prompt()
            .system(LibraryPrompt.Render(user))
            .user(content)
            .call()
            .chatResponse();

    String text = response.getResult() == null
            ? ""
            : response.getResult().getOutput().getText();
    Usage usage = response.getMetadata().getUsage();

    return new AiChatVo(
            text,
            aiProperties.getModel(),
            usage == null ? null : usage.getPromptTokens(),
            usage == null ? null : usage.getCompletionTokens(),
            System.currentTimeMillis() - start,
            false);
}
```

> `useMock()` 判断：`aiProperties.isMock()` 或 key 为空/以 `sk-local` 开头。
> 错误翻译（401/429/超时）用 `try/catch` 包住调用，把异常转成 `BusinessException`，别把堆栈抛给前端。

### 4.3 Controller

```java
@RestController
@RequestMapping("/ai")
@RequiredArgsConstructor
public class AiChatController {

    private final AiChatService aiChatService;

    @PostMapping("/chat")
    public Result Chat(@RequestBody AiChatRequest request,
                       @RequestAttribute("loginUser") LoginUser loginUser) {
        return new Result().success(aiChatService.Chat(request, loginUser));
    }
}
```

## 五、前端实现说明（已完成）

| 文件 | 状态 | 说明 |
|---|---|---|
| `library-web/src/api/ai.js` | ✅ 新增 | `chat(content)`，单独把超时放大到 60s，并带 `silent` 避免和页面内错误提示重复 |
| `library-web/src/views/ai/AiChatView.vue` | ✅ 新增 | 单轮对话页：欢迎态、消息列表、输入框、重试、清空 |
| `library-web/src/router/index.js` | ✅ 修改 | 新增 `/ai` 子路由 |
| `library-web/src/layout/MainLayout.vue` | ✅ 修改 | 侧栏新增「智能 / AI 馆员」入口 + 面包屑分组 |

页面行为：

- **Enter 发送，Shift+Enter 换行**；中文输入法组合期间不会误发（用 `event.isComposing` 判断）；
- 消息只存在**组件内存**，刷新即清空（本版不落库）；
- 失败时在对话里显示错误气泡，可点「重试」重发同一句；
- 不渲染 Markdown（P0 用 `white-space: pre-wrap` 保留换行），避免引入 `markdown-it` + `DOMPurify` 两个依赖和 XSS 风险；
- 请求成功但 `data.content` 为空时显示兜底文案，不会出现空气泡。

## 七、下一版预留（本版不实现）

| 版本 | 内容 | 影响本接口吗 |
|---|---|---|
| P1 | `POST /ai/chat/stream`（SSE，逐字输出） | 不影响，`/ai/chat` 保留为降级通道 |
| P2 | 会话 CRUD + 历史消息表 | 请求体加 `conversationId`（可选字段），旧调用不传仍可用 |
| P3 | 工具调用（查馆藏/查借阅） | 接口不变，只改 Service 里的 `.tools(...)` 和提示词 |
| P4 | 每日额度 | 新增 `GET /ai/quota`，错误消息里带剩余次数 |

> 设计时刻意让 `conversationId` 在 P2 才出现，是为了让 P0 的接口**现在就能定稿**，后面加字段不算破坏性变更。
